알림

한빛미디어 서평단 <나는리뷰어다> 활동을 위해 영상 강의를 제공받아 작성된 리뷰입니다.

그동안 Gemini Pro를 사용하다가 이번에 Claude Pro로 다시 바꾸게 되었습니다. 마침 Claude 강의를 무료로 신청할 수 있어서 수강했습니다.

강의는 Claude Code를 기준으로 CLAUDE.md 작성법부터 Plan Mode, 컨텍스트 관리, Hook/Skill/MCP, 에이전트 팀까지 Claude를 제대로 쓰기 위한 설정과 작업 방식을 다룹니다.

CLAUDE.md는 짧고 계층적으로#

CLAUDE.md는 한 파일만 두는 게 아니라 여러 위치에 나눠서 계층적으로 관리할 수 있습니다.

여러 위치의 CLAUDE.md는 모두 합쳐져서 로드되고, 내용이 충돌하면 더 구체적인(하위) 위치의 설정이 우선 적용됩니다.

그리고 CLAUDE.md에 지시사항이 너무 많으면 오히려 성능이 떨어진다고 합니다. 내용은 적을수록 좋고, 자세한 정보는 하위 파일로 분리해서 연결해 두는 게 좋습니다.
또한, CLAUDE.md는 린터가 아니기 때문에 코드 스타일 같은 린터 규칙은 넣지 않는 게 좋다고 하네요.

방향은 결국 사람이 정해야 한다#

AI가 아무리 발전해도 구현의 방향은 결국 사람이 잡아야 합니다. Claude Code에는 여러 모드가 있는데, 그중 Plan Mode를 이용하면 내 의도에 조금 더 맞게 개발을 진행할 수 있습니다.
특히 새로운 기능을 추가하거나 기존 기능을 바꾸면서 여러 파일을 수정해야 할 때 쓰면 좋습니다.

강의에서 강조한 작업 습관을 정리하면 다음과 같습니다.

  • 컨텍스트 관리 : 컨텍스트가 섞이지 않도록 /context로 사용량을 확인하고, 60%가 넘어가면 /clear나 /compact로 정리합니다. memory.md를 함께 활용하는 것도 좋습니다.
  • 하나의 작업은 하나의 세션 : 사람도 한 가지 일을 끝내고 다음 일을 하는 게 좋은 것처럼, 세션도 작업 단위로 나눕니다.
  • 대용량 데이터 분석 : 데이터를 몽땅 넣고 “해줘"라고 하기보다는, 필터링 스크립트를 실행해서 필요한 데이터만 조금씩 추려 나가야 토큰도 아끼고 정확도도 높일 수 있습니다.

Hook, Skill, MCP 그리고 에이전트#

Claude Code의 주요 기능은 역할로 나눠 보면 이해하기 쉽습니다.

  • Hook : 감시자
  • Skill : 매뉴얼
  • MCP : 외부 연결

에이전트도 동작 방식이 조금 다릅니다. 안티그래비티(Antigravity)에서는 에이전트가 알아서 역할을 나눠서 작업했다면, Claude Code에서는 전문화된 에이전트에게 역할을 할당해서 병렬로 처리한다고 합니다.

이후에는 간단한 실습으로 이 기능들을 직접 다뤄 봅니다. 프로젝트 안에 .claude 폴더를 만들고 MCP 서버를 지정하는 과정을 보면서 Claude Code의 구조를 조금 더 직관적으로 이해할 수 있었습니다.

Windows PC만 쓰다가 Mac을 처음 접했을 때, 앱만 설치하면 알아서 다 되는 줄 알았는데 사실은 내부 폴더 구조와 환경 변수 설정이 있었던 것처럼.. Claude나 다른 LLM도 이런 구조를 알고 나면 조금 더 잘 활용할 수 있지 않을까 싶네요.

에이전트 팀#

현재 기준(2026년 11월)으로 에이전트 팀(Agent Teams)은 실험 기능이라 기본적으로 꺼져 있습니다. 프로젝트의 .claude/settings.json에 아래와 같이 환경 변수를 추가해야 사용할 수 있습니다.

1
2
3
4
5

{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}

에이전트 팀을 쓰면 한 세션이 팀 리더가 되어 작업을 나눠 주고, 팀원 세션들은 각자의 컨텍스트에서 작업하면서 서로 직접 소통합니다. 자세한 내용은 공식 문서에서 확인할 수 있습니다. 이런 기능이 있는 줄 몰랐는데 이번에 알게 돼서 좋았습니다.

Worktree로 작업 나누기#

claude -w 명령어를 쓰면 Git Worktree를 만들어서 그 안에서 Claude Code를 실행할 수 있습니다. 작업마다 별도의 디렉터리에서 세션을 띄우기 때문에 여러 작업을 동시에 진행해도 서로 충돌하지 않습니다.

1

claude -w feature-auth # feature-auth 이름의 worktree에서 Claude Code 실행

Worktree 디렉터리 이름은 한눈에 알아볼 수 있게 짓는 게 중요합니다. 강의에서는 아래처럼 티켓 번호를 포함하는 방식을 소개합니다.

나는 어떻게 활용할 수 있을까?#

몇몇 회사에서는 Claude를 사용하고 있지만, 저희는 아직 도입을 고민하는 단계입니다. 그래도 협업할 때 플러그인을 활용해 프로젝트 설정을 맞춰 두면 좋을 것 같습니다. 사내 프로젝트에서는 CLAUDE.md 내용을 AGENTS.md로 옮기고 작업 방식을 통일해 두면, 다른 AI 도구를 쓰는 팀원과 협업할 때도 편할 것 같습니다.

강의 자체는 Claude를 잘 활용하는 방법을 다루지만, 안티그래비티나 GPT도 결국 개념은 유사하다고 생각합니다.

느낀 점#

강의에서는 지금까지 정리한 기본적인 내용 말고도 아래 내용까지 다뤄 줘서 좋았습니다.

  • Claude Code 소스 코드 유출 사건 때 어떤 기능들이 드러났는지
  • Claude Cowork, Claude Design, Claude Code Security 기능 심화
  • 플러그인과 스킬(Skill)에 대한 좀 더 자세한 내용

이제는 개발 패러다임이 조금 바뀌었다고 생각되네요. 올해도 AI를 어떻게 하면 더 잘 다룰 수 있는지에 대한 책과 영상이 수없이 쏟아졌습니다.

앞으로는 AI를 잘 활용하는 사람이 조금 더 오래? 살아남을 수 있지 않을까요. 그중에서도 토큰을 효율적으로 써서 최소 비용으로 최대 효율을 내는게 좋을 것 같다는 생각도 듭니다.

아키텍처나 알고리즘도 물론 중요하지만, 이제는 그런 지식을 기본으로 깔고 모르는 부분은 AI에게 물어보면서 구조를 잡고 프로젝트를 진행하는 방향으로 바뀌고 있는 것 같습니다.

또한 AI 도구는 결국 계속 바뀔 테니, 특정 도구의 사용법보다는 그 밑에 깔린 개념을 이해해 두는 게 더 중요할 것 같습니다.
